# OCCN-OCPN Transformer

This repository contains an implementation of transformations between **object-centric causal nets (OCCNs)** and **object-centric Petri nets (OCPNs)**. This work was developed as part of the bachelor's thesis *"A Transformation between Object-Centric Causal Nets and Object-Centric Petri Nets"* [1].

The implementation provides:

1.  A transformation from any OCPN to a language-equivalent OCCN.
2.  A transformation from any OCCN to an OCPN that underfits the OCCN while preserving as much behavioral information as possible.

This repository is a fork of the popular open-source process mining library [pm4py](https://github.com/process-intelligence-solutions/pm4py) and contains all contributions, including the evaluation framework used to empirically validate the transformations alongside the formal proofs in the thesis.

## Introduction

Process mining is a discipline that analyzes event data generated by information systems to discover, monitor, and improve real-world processes. A core task in process mining is the automated discovery of **process models** from this data. These models, which capture the observed behavior of a process, are foundational for further analyses, such as identifying bottlenecks or compliance violations.

Many different types of process models exist, each with its own representational biases, strengths, and weaknesses. This makes different models better suited for different use cases. Consequently, the ability to transform one type of model into another is highly valuable. This project provides such a transformation between two important object-centric process models:

  * **Object-Centric Petri Nets (OCPNs):** A widely-used, state-of-the-art process model.
  * **Object-Centric Causal Nets (OCCNs):** A newer formalism proposed to address some of the representational biases found in OCPNs.

## Key Contributions

The following components were implemented and are intended for contribution to the `pm4py` ecosystem:

  * Transformation from OCCN to OCPN
  * Transformation from OCPN to OCCN
  * Algorithms for OCCN play-out (log generation) and replay (conformance checking)
  * Algorithms for OCPN play-out and replay
  * A comprehensive suite of unit tests for all new functionalities

## Transformation: OCCN → OCPN

This transformation converts an Object-Centric Causal Net (OCCN) into an Object-Centric Petri Net (OCPN). The resulting OCPN is guaranteed to **underfit** the original OCCN. This means the OCPN can reproduce all behavior of the OCCN, but it may also allow for additional behavior. The transformation is designed to preserve as much of the original model's constraints as possible.

  * **Primary file:** `pm4py/objects/oc_causal_net/variants/to_ocpn.py`
  * **Tests:** `tests/oc_causal_net_test.py`

### High-Level Explanation

The transformation employs a recursive, bottom-up approach to construct the OCPN. The complex marker group structures of an OCCN are methodically converted into a network of places and silent transitions.

The core ideas are:

1.  **Base Elements:** Every arc in the OCCN becomes a place in the OCPN, and every activity in the OCCN gets corresponding input/output places and a transition.
2.  **Marker Groups:** The intricate logic of OCCN marker groups is modeled using constructs of silent transitions. The transformation recursively builds these constructs by first grouping markers by their key, then by object type, and finally composing the full marker group.
3.  **Binding Object Type:** A crucial element of the transformation is the introduction of an artificial **"binding"** object type. This object acts as a control token that ensures that for any given activity execution, exactly one input marker group and one output marker group are chosen and executed. It orchestrates the complex choices and dependencies within the OCCN's structure.

This approach ensures that all valid behavior of the OCCN is possible in the transformed OCPN. The potential for extra behaviors (underfitting) arises from certain OCCN constraints that cannot be represented in the OCPN formalism. For a comprehensive explanation and formal proofs, please consult the thesis [1].

## Transformation: OCPN → OCCN

This transformation converts an object-centric Petri net (OCPN) into an object-centric causal net (OCCN) that is **language-equivalent**, meaning it describes the exact same set of behaviors.

  * **Primary file:** `pm4py/objects/ocpn/variants/to_oc_causal_net.py`
  * **Tests:** `tests/ocpn_test.py`

### High-Level Explanation

The transformation follows established principles, mapping the core components of an OCPN to their OCCN counterparts. In essence:

  * **Places** in the OCPN are converted into unlabeled activities in the OCCN.
  * **Arcs** connected to transitions become markers. Non-variable arcs are translated to markers with cardinality `(1,1)`, while variable arcs become markers with cardinality `(0,*)`.

A special challenge arises when a transition has multiple outgoing variable arcs for the same object type. OCPN semantics require that an object token consumed by the transition is duplicated and sent to *all* successor places. To preserve this behavior, the transformation introduces a special **auxiliary activity** (`τ`) for some activities in the OCCN. This activity ensures that the object is correctly distributed to all required successors, thus mimicking the OCPN's duplication logic.

For a detailed technical explanation and the formal proof of correctness, please refer to the thesis [1].

## Evaluation

In addition to the formal mathematical proofs of correctness, an empirical evaluation was conducted to validate the transformations.

### Approach

Since the languages (i.e., all possible binding sequences) of the process models are often infinite or intractably large, a full language comparison is not feasible. Instead, we employed a **play-out and replay** approach:

1.  **Play-out:** Generate a large, randomized subset of sequences from the source model's language.
2.  **Replay:** Check if every generated sequence can be successfully replayed on the target model.

For each of the three event logs evaluated, we performed four distinct experiments:

  * Mine an OCPN, transform it to an OCCN:
    1.  Play-out from the mined OCPN, replay on the transformed OCCN.
    2.  Play-out from the transformed OCCN, replay on the mined OCPN.
  * Mine an OCCN, transform it to an OCPN:
    1.  Play-out from the mined OCCN, replay on the transformed OCPN.
    2.  Play-out from the transformed OCPN, replay on the mined OCCN.

### Evaluated Datasets (OCELs)

The evaluation was performed on three object-centric event logs (OCELs):

1.  **Running Example:** The small, illustrative example used throughout the thesis.
2.  **Container Logistics:** A real-world logistics log from the [OCEL standard website](https://ocel-standard.org/event-logs/simulations/logistics/).
3.  **Procure-to-Pay (P2P):** A classic P2P example log from the [OCEL standard website](https://ocel-standard.org/event-logs/simulations/p2p/).

All 12 models used in the evaluation can be found in the `evaluation/models/` directory, along with the sets of objects used for their play-out.

### Results

The table below summarizes the replayability results, where `n` is the number of binding sequences generated and replayed.

| Dataset              | OCPN → OCCN (Play-out OCPN, Replay OCCN) | OCPN → OCCN (Play-out OCCN, Replay OCPN) | OCCN → OCPN (Play-out OCCN, Replay OCPN) | OCCN → OCPN (Play-out OCPN, Replay OCCN) |
| -------------------- | :-------------------------------------------: | :-------------------------------------------: | :-------------------------------------------: | :-------------------------------------------: |
| **Running Example** |                100%, `n=4,100k`                 |               100%, `n=4,000k`               |                 100%, `n=76k`                 |                1.5%, `n=2,400k`                |
| **ContainerLogistics** |               100%, `n=2,600k`                |                100%, `n=700k`                 |                 100%, `n=76k`                 |                 10.5%, `n=4,300k`                |
| **Procure-to-Pay** |               100%, `n=3,600k`                |               100%, `n=3,500k`                |                100%, `n=130k`                 |               100%, `n=4,200k`                |

These results empirically confirm the theoretical properties of the transformations:

  * The **100% replayability** in the first two columns supports the claim of **language equivalence** for the OCPN-to-OCCN transformation.
  * The **100% replayability** in the third column shows that all behavior from the source OCCN is preserved in the transformed OCPN.
  * The **\<100% replayability** in the fourth column demonstrates the **underfitting** property: the transformed OCPN allows for more behavior than the original OCCN. The 100% replayability for the P2P dataset presents an edge case in which the transformed OCPN is behaviorally equivalent to the OCCN.

For a detailed analysis of these results, please see the thesis [1].

### Play-out and Replay Implementation
This repository also contributes the underlying play-out and replay algorithms for both OCCNs and OCPNs. The play-out algorithms are highly optimized, using extensive memoization to avoid redundant computations and efficiently explore the model's behavior.

  * **Concerned files:** `pm4py/algo/simulation/playout/oc_causal_net`, `pm4py/algo/simulation/playout/ocpn`
  * **Tests:** `ests/oc_causal_net_simulation_test.py`, `tests/ocpn_simulation_test.py`, `tests/oc_causal_net_semantics_test.py`, `tests/ocpn_semantics_test.py`

For a technical explanation, please refer to the thesis [1].


## Installation

To set up your environment and run the code, please follow these steps:

1.  **Create and activate a virtual environment:**

    ```bash
    python -m venv .venv
    source .venv/bin/activate
    # On Windows, use: .venv\Scripts\activate
    ```

2.  **Install pm4py dependencies:**

    ```bash
    pip install -r requirements_complete.txt
    ```

3.  **Install this forked version of pm4py in editable mode:**

    ```bash
    pip install -e .
    ```

4.  **Install additional packages:**

    ```bash
    pip install rich
    ```

As a starting point, you may run the evaluation by invoking `python evaluation/run_evaluation` from the root directory.

## Usage
To convert an OCPN to its corresponding OCCN, discover an OCPN from an OCEL, convert the resulting dictionary representation to an OCPetriNet object, and conduct the conversion:
```python
from pm4py.objects.ocpn import factory as ocpn_factory
from pm4py.objects.ocpn import converter as ocpn_converter

ocel = pm4py.read_ocel2(os.path.join("evaluation", "event_logs", ocel_name))
ocpn_dict = pm4py.discover_oc_petri_net(ocel)
ocpn = ocpn_factory.create(ocpn_dict)

occn = ocpn_converter.apply(ocpn, variant=ocpn_converter.Variants.TO_OC_CAUSAL_NET)
```

To convert an OCCN to its corresponding OCPN, discover or manually create an OCCN, and conduct the conversion:
```python
from pm4py.objects.oc_causal_net import converter as occn_converter

occn = ... # see evaluation/container_logistics_occn.py for an example
ocpn = occn_converter.apply(occn, variant=occn_converter.Variants.TO_OCPN)
```
